## 第一部分：用户手册

### 1. 软件简介

信息采集官是一套面向内容创作者的**多平台智能采集与转录管理系统**。用户输入一条视频链接，系统自动完成平台识别、视频下载、语音转文字、质量校验、知识库归档的全流程，无需人工干预。

### 4. 功能详解

#### 4.1 支持的平台

| 平台 | 采集方式 | 转录方式 | 预计耗时 |
|------|---------|---------|---------|
| 抖音 | Chrome CDP 读字幕（优先） | CDP字幕 / Whisper GPU | 20秒 - 3分钟 |
| B站 | yt-dlp 下载 | Whisper GPU | 1-3分钟 |
| YouTube | yt-dlp 下载 | Whisper GPU | 1-3分钟 |
| 小红书 | yt-dlp / MediaCrawler | Whisper GPU | 1-5分钟 |
| 快手 | yt-dlp 下载 | Whisper GPU | 1-3分钟 |
| 视频号 | 自研 sph_to_feishu.py | Whisper GPU | 1-3分钟 |
| 知乎 | MediaCrawler 搜索 | - | - |
| X/Twitter | FxTwitter API + Jina | - | - |

#### 4.2 转录引擎对比

| 引擎 | 类型 | 速度 | 中文准确度 | 依赖 |
|------|------|------|-----------|------|
| faster-whisper/base | 本地GPU | 快 | 良好 | CUDA GPU |
| faster-whisper/medium | 本地GPU | 中等 | 较好 | CUDA GPU |
| Paraformer | 在线API | 快 | 最优 | 联网+API Key |
| 飞书妙记 | 云服务 | 慢 | 好 | 飞书账号 |

#### 4.3 降级链机制

系统为每个平台配置了 3-5 级自动降级，确保任务不会因单一环节失败而中断：

**抖音降级链：**
```
策略1: Chrome CDP 直取 + 质量校验  (90秒超时)
   ↓ 失败/超时/字幕质量不合格
策略2: 自动启动 Chrome + CDP 重试  (120秒超时)
   ↓ 失败/超时
策略3: yt-dlp 下载完整视频 → Whisper/base GPU 转录  (600秒超时)
   ↓ 失败/超时
策略4: yt-dlp 仅下载音频 → Whisper/tiny 快速转录  (300秒超时)
   ↓ 失败/超时
策略5: yt-dlp 下载 → Paraformer 在线 API  (300秒超时)
```

**CDP 字幕质量校验规则：**
- 中文字符 ≥ 50 个
- 中文占比 ≥ 15%
- 行数 > 2 或 汉字 ≥ 100
- 话题标签 ≤ 5 或 汉字 ≥ 200

#### 4.4 输出格式

转录结果自动生成结构化 Markdown 笔记：

```markdown
---
title: "视频标题"
platform: 抖音
source: https://v.douyin.com/xxxxx/
date: 2026-08-06
engine: faster-whisper/base
tags:
  - 逐字稿
  - 抖音
---

# 视频标题

> **来源**: https://v.douyin.com/xxxxx/
> **平台**: 抖音
> **引擎**: faster-whisper/base

## 逐字稿

[完整转录文本...]
```

同时可通过飞书 API 同步至多维表格，包含：标题、平台、作者、链接、互动数据、爆款指数、采集时间等字段。

## 第二部分：技术说明书

### 1. 软件架构

本软件采用**管道-过滤器（Pipeline-Filter）架构模式**，数据从输入到输出经过一系列有序的处理阶段，每个阶段可独立替换和降级。

```
输入(链接/文件) → 识别 → 采集 → 转录 → 校验 → 归档
                  ↓       ↓       ↓       ↓
               路由器   多策略   多引擎   双通道
```

### 2. 模块划分

#### 2.1 统一入口模块（collector.py）
- **功能**：命令行参数解析、平台链接识别、降级链调度
- **核心类/函数**：`detect()`, `run_fallback_chain()`, `try_step()`, `cmd_pipeline()`
- **创新点**：多级降级引擎，每步独立超时与异常捕获

#### 2.2 飞书通信模块（feishu/）
- **文件**：`client.py`（API客户端）、`bitable.py`（多维表格管理）、`schema.py`（表结构定义）
- **功能**：Token自动管理/刷新、表自动创建/字段补全、去重写入、分页查询
- **依赖**：飞书开放平台 API

#### 2.3 抖音采集模块（scripts/collect_douyin_*.py 系列）
- **采集链路**：`profile_opencli.py`（读取作品列表）→ `media_responses.py`（获取媒体流）→ `download_tracks.py`（下载音频+视频+合并）→ `normalize_records_media.py`（规范化记录）
- **转录链路**：`transcribe_douyin_fast.py`（逐条转录+断点续传）→ `sync_douyin_to_obsidian.py`（写入Obsidian+生成分析报告）
- **辅助工具**：`retry_douyin_failed_media.py`（失败重试）、`merge_douyin_retry_media.py`（结果合并）、`split_douyin_manifest.py`（分批处理）、`archive_douyin_metadata_index.py`（归档索引）

#### 2.4 多人采集模块（scripts/x_capture.py）
- **功能**：Twitter/X 推文采集，通过 FxTwitter API + Jina 提取正文、图片、视频等结构化数据
- **输出**：按原始顺序重组 article.md → 写入 Obsidian + 飞书

#### 2.5 转录引擎模块
- **transcribe_local.py**：双引擎（faster-whisper GPU/CPU + Paraformer 在线），支持批量文件，自动提取音频轨道
- **transcribe_douyin_fast.py**：抖音专用快速转录，GPU优先，断点续传
- **transcribe_batch.py**：MediaCrawler 下载视频 → Whisper → Obsidian 笔记补全的完整桥接

#### 2.6 数据同步模块
- **sync_douyin_to_obsidian.py**：生成逐条笔记 + 账号索引 + 分析报告（关键词统计、钩子类型分析、内容分类）
- **sync-to-feishu.js**：Node.js版飞书同步（账号+作品两表联动）
- **media_crawler_bridge.py**：MediaCrawler JSONL → 统一格式转换

#### 2.7 GPU 自动检测模块（utils/gpu_config.py）
- **功能**：首次运行探测 CTranslate2 CUDA 支持 → 写入 `.gpu_config.json` → 后续复用缓存
- **输出**：`(device, compute_type)` 元组供所有转录脚本使用

### 3. 数据流设计

```
┌─────────────────────────────────────────────────────────┐
│ 流① 抖音账号采集（最长链路，8步）                         │
│ 账号URL → OpenCLI读取作品列表 → 获取媒体流地址            │
│ → 下载视频+音频+ffmpeg合并 → 规范化记录                  │
│ → faster-whisper逐条转录 → Obsidian笔记+分析报告          │
│ → 飞书多维表格同步                                       │
├─────────────────────────────────────────────────────────┤
│ 流② 飞书机器人实时转录                                   │
│ 飞书收到链接 → 平台检测 → 抖音:CDP直取 / 其他:yt-dlp+转录  │
│ → Obsidian归档 → 飞书回复摘要+逐字稿文件                   │
├─────────────────────────────────────────────────────────┤
│ 流③ MediaCrawler关键词搜索                               │
│ 关键词 → MediaCrawler采集 → JSONL桥接转换 → 批量转录       │
│ → Obsidian补全 → 飞书入库                                │
├─────────────────────────────────────────────────────────┤
│ 流④ 全自动流水线（collector.py）                          │
│ 链接/文件 → 平台识别 → 3-5级降级链执行 → 质量校验         │
│ → Obsidian归档                                           │
└─────────────────────────────────────────────────────────┘
```

### 4. 关键技术实现

#### 4.1 多级降级引擎

```python
def run_fallback_chain(chain_name, steps):
    """按顺序执行降级链，每步独立超时"""
    for i, step in enumerate(steps):
        try:
            result = try_step(step["label"], step["fn"], step["timeout"])
            return result  # 成功即返回
        except (StepFailed, StepTimeout):
            continue       # 失败走下一级
    return {"transcript": None}  # 全部失败
```

每个步骤在独立线程中执行，主线程控制超时。超时后线程被放弃但不阻塞，立即触发下一级策略。

#### 4.2 字幕质量校验算法

针对 CDP 提取的字幕数据进行四维度检测：
- 中文字符计数（正则 `[一-鿿]`）
- 中文密度计算（中文字符/总字符）
- 行数结构分析
- 话题标签密度检测

任一维度不达标立即抛异常触发降级。

#### 4.3 断点续传机制

转录 manifest 在每条视频处理完成后实时写入磁盘，启动时先读取已有 manifest 建立已完成集合，后续处理自动跳过已完成项。
